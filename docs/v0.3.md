# Volta v0.3 plan and acceptance checks

1. Keep the room server independent of screen navigation. Returning from a race clears the race and readiness while keeping the same room link and connected drivers. Verify pause, abort, home, lobby, rematch and phone reconnect.
2. Make the host the authority for kart colors. Verify simultaneous selection, a new join after a color change, and the actual color in each of the three 3D models.
3. Add mystery boxes that replace the held item and keep activation separate from collection. Verify multiplayer collection, item effects, countdown, pause and time trials.
4. Reduce the Android rendering workload first, then measure the release APK on the affected Google TV. Compare the same track and four phones for baseline and v0.3. Use 30 FPS sustained as the release floor (33.3 ms per frame) and 60 FPS as a stretch goal (16.7 ms). Run one, four and six views for at least one minute each. Collect a Perfetto trace if four views fall below target and compare game UI, raster and GPU work. Check input latency, split-screen readability and race-clock progression during frame drops.
5. Run static analysis, Dart tests and browser controller tests. Build and smoke-test native targets separately.

## Implementation and review

- The room lives for the app session, independent of Home, lobby, results and race screens. Leaving a paused race resets readiness and inputs while keeping sockets, reserved colors and the QR address. Restarting the app starts a fresh room. Drivers can still leave individually.
- Color selection is authoritative on the host. Joined drivers receive an unused color. Phones mark other drivers' colors unavailable, and the host rejects conflicting claims even if two requests arrive together. Starting a race locks the host's current driver selections before the camera intro.
- The host spaces two to four rows of three purple mystery boxes around the track, based on lap length. Boxes respawn after ten seconds. Collecting a box replaces the held item without changing speed. The phone shows an item button with an icon and label; the host HUD shows an icon per viewport. Each item is used through a one-shot input, also available on E and Enter for keyboard players.
- Android renders the 3D scene at the native viewport pixel ratio with a 60 FPS ceiling. The chase camera fades the scene into a painted-color horizon before its far clip. Long tracks split their road mesh into frustum-cullable sections, while nearby geometry keeps its original detail. The existing Android budget still skips clouds and tire particles and keeps the low anti-aliasing tier. The lobby has the full track overview. The simulation steps long frames in chunks of at most 50 ms with a 200 ms catch-up limit.
- Flutter Scene 0.24.3 documents native Windows support with Flutter 3.47.1 or later for release, and the Windows runner must enable Flutter GPU on its Dart project. Its web backend uses WebGL2. These renderer capabilities were checked in the pinned package. The Windows and Linux runners enable Flutter GPU. The browser uses the WebGL2 backend.

## Items

| Item | Effect |
| --- | --- |
| Banana | Drops a peel behind the kart. Contact stops and spins a rival for 0.6 seconds. |
| Oil | Drops a slick behind the kart. Contact slows a rival for 1.6 seconds. |
| Rocket | Homes toward a rival ahead within range. A hit stops and spins the rival for 0.9 seconds. |
| Leader slow | Slows the leading active driver for three seconds. |
| Comeback | Raises the last active driver's speed limit and acceleration by 50% for four seconds. |
| Position swap | Has a 4% roll chance. Exchanges position and checkpoint progress with a random active rival on the same lap, preserving personal lap records. |
| Turbo refill | Refills the normal boost meter. |

Traps expire after 15 race seconds or a hit. An item stays held if its activation condition is unmet.

## Automated TV benchmark

With the TV connected through ADB, build and run the benchmark. It installs the APK and autostarts four bots on Brasil using all three kart models and the production simulation and renderer. Phones remain unnecessary for this graphics test.

```sh
flutter build apk --release --dart-define=VOLTA_BENCHMARK=true
python3 tool/benchmark_tv.py build/app/outputs/flutter-apk/app-release.apk
```

After five seconds of warm-up, the test samples 60 seconds. It gates on the slower rate of scene ticks and Flutter raster completions, and the higher p95 interval across the two. It also reports Flutter UI and raster p95 and exits with a passing or failing status. The default gate allows 29.5 FPS for a nominal 30 FPS target and requires p95 frame interval at or below 50 ms. To isolate horizon and culling changes, repeat on the same TV at the same resolution with `--dart-define=VOLTA_FULL_DRAW=true`. Run a normal release build to return to the player lobby. The benchmark measures the Flutter scene pipeline. Use a Perfetto or Android Studio system trace to confirm display presentation and GPU stalls during a real four-phone session. [Android Studio system traces](https://developer.android.com/studio/profile/jank-detection)

## Flutter upgrade and native options

The checkout uses Flutter 3.47.2 and Dart 3.13.2. The official archive offers Flutter 3.50.0 with Dart 3.14.0. Install the candidate SDK alongside the existing one, build the same commit, and compare both APKs on the same TV. Keep the resolution, horizon flag, and device settings identical. [Flutter SDK archive](https://docs.flutter.dev/install/archive)

The Android host already enables Flutter GPU. First measure whether the extra split-screen cost is on the UI thread, raster thread, GPU, or compositor. If the simulation dominates UI time, profile track sampling and contacts and compare a batched Dart FFI C kernel against Dart AOT. If raster or GPU time dominates, investigate Flutter Scene and Android backend traces before changing the renderer. A custom native Vulkan renderer would also need to own assets, cameras, and maintenance for this Android path. [Dart C interop](https://dart.dev/interop/c-interop) · [Flutter Impeller](https://docs.flutter.dev/perf/impeller)
