# Volta v0.3 plan and acceptance checks

1. Keep the room server independent of screen navigation. Returning from a race clears the race and readiness while keeping the same room link and connected drivers. Verify pause, abort, home, lobby, rematch and phone reconnect.
2. Make the host the authority for kart colors. Verify simultaneous selection, a new join after a color change, and the actual color in each of the three 3D models.
3. Add original track pickups with random, automatic effects and a respawn delay. Verify multiplayer collection, both effects, countdown, pause and time trials.
4. Reduce the Android rendering workload first, then measure the release APK on the affected Google TV. Compare the same track and four phones for baseline and v0.3. Use 30 FPS sustained as the release floor (33.3 ms per frame) and 60 FPS as a stretch goal (16.7 ms). Run one, four and six views for at least one minute each. Collect a Perfetto trace if four views fall below target and compare game UI, raster and GPU work. Check input latency, split-screen readability and race-clock progression during frame drops.
5. Run static analysis, Dart tests and browser controller tests. Build and smoke-test native targets separately.

## Platform rollout

| Target | Stack and next milestone |

| Windows PC | Add the Flutter Windows runner on a Windows dev machine. Verify Flutter Scene’s Windows backend and shader bundle on the pinned toolchain first, then test keyboard, Windows Firewall prompts, LAN hosting, race history and four-view rendering before packaging. |
| Web | Spike the pinned Flutter Scene web renderer and shader build with a keyboard-only race first. Browser builds require platform-specific adapters for desktop IO and native APIs. A browser cannot listen for phone WebSocket connections, so preserve the existing protocol using a separately hosted room service and validate HTTPS/WSS and origins before offering phone multiplayer. |

Windows and browser hosting are rollout milestones. The phone controller is already a browser app.

## Implementation and review

- The room lives for the app session, independent of Home, lobby, results and race screens. Leaving a paused race resets readiness and inputs while keeping sockets, reserved colors and the QR address. Restarting the app starts a fresh room. Drivers can still leave individually.
- Color selection is authoritative on the host. Joined drivers receive an unused color. Phones mark other drivers' colors unavailable, and the host rejects conflicting claims even if two requests arrive together. Starting a race locks the host's current driver selections before the camera intro.
- The host handles pickup placement, collision, random outcome, cooldown and respawn. It shows pickup feedback in the HUD and through existing phone telemetry. Purple boxes appear three per row. The host spaces three to twelve rows around the track based on length, leaving a gap at the start. Each pickup randomly refills boost, grants a 1.25-second asphalt speed burst while accelerating, or triggers a slow pulse. Each box reappears after eight seconds. A pulse slows the nearest active rival within 320 track units for two seconds. It refills the collector's boost if there is no nearby rival.
- On Android, three or more views start with a 960-pixel long edge; one or two views use up to 1280. Adaptive scaling can lower the 3D resolution further. The HUD stays at native UI resolution and refreshes at 15 Hz. The 3D renderer targets 30 FPS. The Android preset also skips tire particles and clouds, reduces roadside scenery, and uses the lowest renderer quality tier. Start tiles are instanced on all hosts. The simulation splits long frames into steps of up to 50 ms, with a 200 ms catch-up limit.
- Flutter Scene 0.24.3 documents native Windows support with Flutter 3.47.1 or later for release, and the Windows runner must enable Flutter GPU on its Dart project. Its web backend uses WebGL2. These renderer capabilities were checked in the pinned package. Volta's Windows and browser hosts still require the work in the rollout table.

Build a test APK with frame logs enabled, then follow the TV installation guide.

```sh
flutter build apk --release --dart-define=VOLTA_FRAME_STATS=true
adb install -r build/app/outputs/flutter-apk/app-release.apk
adb logcat -s flutter | rg 'Volta:'
```

Each five-second report includes scene tick FPS, p95 tick interval and the number of player views. Capture a full race on the target TV before reporting a sustained FPS result. The existing six-view Mac profile numbers in the README are historical.

## Verification

Static analysis, the Dart suite, and the browser controller tests pass. Automated coverage includes pause-to-lobby, race clock progression at a 100 ms frame interval, persistent room identity through Home and keyboard practice, occupied colors, pickup count on short and long tracks, each of the three pickup effects, and pickup cooldown.

The TV acceptance gate is pending a run on the affected hardware with four phones. The tests exercise room behavior and game rules without measuring TV GPU throughput.
